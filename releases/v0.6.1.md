# FileEx Release v0.6.1

**Release Date:** October 2026

## 🌟 What's New in v0.6.1

### 🔧 Dynamic Version Resolution & Accurate Status Reporting
- **Dynamic Crate Versioning**:
  - Replaced legacy static version strings in Tauri's backend (`get_install_info`) with dynamic compile-time crate version detection (`env!("CARGO_PKG_VERSION")`).
  - Fixed an issue where upgrading from `v0.5.4` to `v0.6.0` continued to display `v0.5.4` inside the TitleBar and Settings dialog due to a hardcoded version string in the Rust binary.
  - The TitleBar, Settings drawer, and update hooks now dynamically reflect the exact running binary version.
- **Update Hook Cache Invalidation**:
  - The silent background update hook (`useAppUpdateCheck`) now validates cached updates directly against the running version. Upgrading to a new release immediately clears update badges instead of waiting for the 6-hour cache TTL to expire.

### 🛡️ Synchronous Package Installation & Elevated Auth Handling
- **Awaited Polkit & Package Manager Execution**:
  - Switched Linux `.deb` package installation (`pkexec apt-get install -y <deb_path>`) from unmonitored background spawning to synchronous blocking execution via `tokio::task::spawn_blocking` and `.output()`.
  - FileEx now stays in the "Installing update..." state until Polkit authentication and `apt-get` installation conclude, accurately distinguishing between successful installation, cancelled authentication, and system error logs.

### 🔄 One-Click Application Restart Flow
- **Native Tauri Restart Command**:
  - Added a backend `restart_app` command leveraging Tauri's native `app_handle.restart()` API.
- **Immediate Restart Action Card**:
  - Upon successful installation, the Settings Updates tab presents a confirmation card with an immediate **"Restart FileEx Now"** button, allowing users to transition directly to the updated executable.
